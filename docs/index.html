Start

Get started in a minute.

Install the package, grab a builder, and render a template against any model. Zero configuration — the built-in pipes are already registered.

1 · Install

terminal
dotnet add package NgSharp

2 · Render your first template

Result

Hello, Ada!

using NgSharp;

var html = await HtmlBuilder.Default.BuildFromTemplateAsync(
    template, new { Name = "Ada" });
<h1>Hello, {{ Name }}!</h1>

The model can be any object, a System.Text.Json.JsonElement, or a pre-built NgElement. Values are HTML-escaped automatically.

Start

How it works.

NgSharp parses your template into an immutable AST once, then a stateless renderer walks that tree against your model. No code generation, no per-render state — which is where its guarantees come from.

Template → Lexer + tree builder → Immutable AST → Stateless renderer + model → HTML
InterpretedNo runtime code generation — nothing to Roslyn-compile or emit at first use, so it starts without the codegen cost Razor and Handlebars pay.
Immutable & thread-safeThe AST never mutates and the renderer holds no state, so one Compiled template renders concurrently across threads.
AOT & trim cleanOn the JsonElement / NgElement path; the reflection-based object overload and component binding are opt-in.
Zero dependenciesOnly System.Text.Json — in the shared framework on .NET 8+, a single package on netstandard2.1.

Start

Good to know.

A handful of behaviours worth knowing before your first render — the things that would otherwise surprise you.

HtmlBuilder.Default is a fresh builder. Every access returns a new instance pre-loaded with the built-in pipes. Capture it once — var builder = HtmlBuilder.Default; — then register and render on that same instance; registering on one Default and rendering on another loses the registration.

Output is verbatim. Rendering emits your template's whitespace exactly as written — newlines and indentation included, and correctly inside <pre> / <textarea>. Want it collapsed? Call the opt-in HtmlBuilder.MinifyHtml on the result yourself.

Pipes use the current culture. date, number and largeNumber format with the thread's CultureInfo — set CultureInfo.DefaultThreadCurrentCulture for deterministic output. The sample outputs on this page are en-US.

The expression language is small. Paths, indices, .Count / .Length, literals, == != < > <= >=, &&, ||, ternary and pipes. No arithmetic, no !, no method calls; ordering comparisons are numeric. Test existence with a comparison — [if]="Items.Count > 0", not [if]="Items".

Truthiness is strict; misses are silent. Only a real boolean is truthy, and a path that doesn't resolve renders empty rather than throwing. Empty templates and unknown pipes do throw.

Async is ergonomic, not concurrent. BuildFromTemplateAsync returns an already-completed Task — rendering is CPU-bound. Compile(template).Render(model) is the synchronous path.

Components use reflection. Unlike pipes and directives, component [prop] binding is reflection-based and binds scalar properties only; preserve those members under trimming / Native AOT.

Where it fits. Reach for NgSharp when you need HTML-correct, escaped output with a compile-free cold start and zero dependencies — Native AOT, trimming, serverless, short-lived processes.

For a full view engine, use Razor; for maximum warm-loop throughput on long-lived servers, Fluid / Handlebars / RazorLight are faster.

Conditionals @if · @else · [if]

Use the block form @if (…) { } @else if (…) { } @else { }, or the attribute form [if]="expr" to keep a single element. Conditions accept comparisons and && / ||; truthiness is strict — only a real boolean is truthy.

Loops @for · [for] · [not-empty]

Repeat a body once per item with @for (Items) { } — each item becomes the local context, and outer scope is still reachable. [for]="Items" repeats a single element; [not-empty]="Items" renders only when the collection is non-empty.

Performance

Compile once, render many.

Parsing is the bulk of a one-shot render. When you render the same template repeatedly, compile it once: NgSharp parses the AST and folds its static skeleton — text, comments and fixed-attribute tags — into precomputed constants (a partial-evaluation pass, no code generation), so each render pays only for the data-dependent parts.

The result is immutable and the renderer stateless, so a compiled template is safe to render concurrently. This is the warm path measured in the benchmarks below.

C#
var tpl = HtmlBuilder.Default.Compile(
    "<li>{{ Name }}</li>");

foreach (var user in users)
    output.Append(tpl.Render(user));
note

API reference

The public surface, in full.

Every public type is documented with XML comments, so the same descriptions surface in your IDE's IntelliSense.

class

HtmlBuilder

The entry point: registers pipes/directives/components and renders templates. HtmlBuilder.Default comes pre-loaded with the built-in pipes.

static HtmlBuilder Default { get; }property

A new builder pre-loaded with the built-in pipes (date, number, largeNumber, upper, image).

Task<string> BuildFromTemplateAsync(string template, object | JsonElement | NgElement model)3 overloads

Renders a template against a model. The object overload reads it directly via reflection (honors [JsonPropertyName]/[JsonIgnore], not custom converters); the JsonElement overload is reflection-free with full System.Text.Json fidelity (AOT / trim); the NgElement overload is the hot-path opt-in.

CompiledTemplate Compile(string template)method

Parses the AST once and returns a reusable CompiledTemplate (parse-once / render-many).

void RegisterPipe<T>() · RegisterComponent<T>() · RegisterDirective<T>()methods

Registers a pipe / component / directive. Each T is instantiated via its parameterless constructor.

IReadOnlyDictionary<string, …> Pipes · Directives · Componentsproperties

The registered extensions, keyed by name.

sealed class

CompiledTemplate

A template parsed once and rendered many times, from HtmlBuilder.Compile. Immutable AST + stateless renderer — safe to render concurrently.

string Render(object | JsonElement | NgElement model)3 overloads

Renders the compiled template against a model — same three model kinds as BuildFromTemplateAsync.

class

NgElement

The data model — a lightweight, read-only JSON value tree. Usually built for you; construct one directly for the hot path or to inspect data.

static NgElement FromJson(JsonElement json) · FromObject(object value)factories

FromJson is reflection-free (AOT / trim safe); FromObject walks a CLR object via reflection — the fastest path, skipping the JSON round-trip.

NgElement SelectToken(string path)method

Resolves a path — property names, dotted paths, array indices ("Items[0].Name"), and the computed .Count / .Length.

string GetString() · int? GetInt() · double? GetDouble() · bool? GetBoolean() · DateTime? GetDateTime() · …getters

Typed accessors for the leaf value (also GetLong, GetDecimal, GetFloat); each returns null when not convertible.

object Value · JsonValueKind ValueKind · Children · Properties · int Count · Length · string Pathproperties

The scalar value and kind, the child/property collections, the computed Count / Length, and the full dotted Path.

API reference · extend

Extend the engine.

Three interfaces grow the template language: IPipe (value transforms), IDirective (host-element mutations) and IComponent (server components). Implement one, register it, use it.

Pipes and directives are plain interface calls (reflection-free); component property binding uses reflection, so preserve those members under trimming / Native AOT.

Custom pipe IPipe

Result
AL 
public class InitialsPipe : IPipe
{
    public string PipeName => "initials";

    public string Transform(string tag, NgElement value, string arg)
    {
        var name = value.GetString() ?? "";
        return string.Concat(name.Split(' ')
            .Where(p => p.Length > 0)
            .Select(p => char.ToUpper(p[0])));
    }
}

builder.RegisterPipe<InitialsPipe>();
<span class="avatar">{{ Name | initials }}</span>

// Name = "Ada Lovelace"

Benchmarks

Honest numbers.

The same template rendered by six .NET engines — cold (first parse + render) and warm (pre-parsed, render only). Lower is better. NgSharp interprets templates, so it does no runtime code generation — that is the whole trade-off below.

What's measured. The same logical document in each engine's own dialect, rendering byte-identical output — a product catalogue of 8 categories × 12 products (96 items) with nested loops, several fields per item, and two conditionals.

The honest read. NgSharp's structural edge is cold start against engines that compile to code — RazorLight and Handlebars pay a large codegen cost up front (~125–400× NgSharp's), which is exactly what hurts in serverless, Native AOT and short-lived processes.

Among the lean interpreters it starts faster than Stubble and Scriban, and trails only Fluid — while compiling nothing.

Warm — steady-state render of a fresh model — NgSharp (47 µs) lands second, ahead of Fluid (48 µs) and Handlebars (50 µs) and behind only RazorLight's compiled delegate (37 µs); Scriban (155 µs) trails.

Two choices get it there with no codegen: Compile() folds the static skeleton once (partial evaluation), and the data context is a flat, dictionary-free node array — cheap to build, cheap to scan.

RazorLight stays a touch quicker in steady state, but pays for it with a cold start hundreds of times slower; NgSharp keeps zero codegen, Native-AOT / trim safety and zero third-party dependencies.

The honest read. Cold, NgSharp is 40–114× faster — both rivals compile, and RazorLight emits a full Roslyn assembly (allocating 7 MB), exactly the codegen tax that hurts in serverless / AOT / short-lived processes.

Warm, the two compiled delegates edge NgSharp's fresh-model path (RazorLight 354, Handlebars 398 vs 482 µs) by reading your object directly — but reusing a prebuilt NgElement context (305 µs) makes NgSharp the fastest of the three. Its warm render breaks down as parse ≈ 113 µs (once), model → tree ≈ 177 µs, pure render ≈ 305 µs (~0.6 µs/node across four pipes, four binding kinds, block conditionals, a ternary and a component).

NgSharp writes it in one interpreted, native template; Handlebars needs nine registered helpers, RazorLight needs the Roslyn compiler.
